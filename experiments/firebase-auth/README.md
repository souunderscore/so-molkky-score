## 利用者から見た動作

- 管理画面ではパスコードだけを入力する。Googleログインやメールアドレス入力は要求しない。
- 忘れた場合は、自分で設定した秘密の質問へ回答する。
- 裏側では管理ログイン用と復旧用の2つのFirebase認証アカウントを分離する。
- メンバー用リンクと入力担当端末の権限は、管理者用Firebaseアカウントとは別に管理する。
- Firebaseの任意のユーザーを管理者として扱わない。設定済みUIDへの一致を必ず確認する。

## 構成

1. Workerで入力にサーバー側の秘密を用いたHMAC-SHA256を適用する。
2. 管理用/復旧用で用途を分け、別のFirebase認証アカウントのパスワードとして検証する。
3. Firebase標準のEmail/Password認証が、管理されたパスワードハッシュによる照合を行う。
4. Workerは認証後、独自の管理セッションを発行する。Firebaseトークンはブラウザへ渡さない。
5. 管理セッションの世代をサーバーで確認し、パスコード変更時に全セッションを失効する。

HMACだけでパスワードを照合する方式ではありません。HMACは前処理で、重い照合はFirebaseが担います。
秘密値は本番ではCloudflare Secretsに設定し、Git・画面・ログへ含めません。
秘密の回答をEmail/Passwordアカウントの資格情報として扱うのは独自設計です。
Firebase標準機能に秘密の質問が備わっている、という意味ではありません。
質問自体の管理・本人確認・再設定・誤入力制限はアプリ側で実装する必要があります。

## 確認できたこと

### 単体・状態遷移モデル: 11件成功

- 管理用と復旧用の入力の分離、サーバー秘密による資格情報の分離。
- 入力の完全一致（前後空白・全半角を自動補正しない候補）。
- パスコードが平文のままFirebaseへ渡らないこと。
- 別UID、無効な入力、不正な応答、ネットワーク失敗、上流の利用制限を成功扱いにしないこと。
- パスコード変更前の管理セッションが全て無効になること。
- 変更処理中に開始済みのログインが旧世代のセッションを発行できないこと。
- 外部認証側の変更に失敗した場合、旧セッションを復活させず変更中の状態を保持すること。
- 失敗試行をサーバーで先に予約し、制限後は上流認証を呼ばないこと。

セッション・試行回数の保存先はここではテスト用メモリ実装です。
本番ではDBの原子的な更新と待ち時間・有効期限を持つ実装が必要です。
この実装だけで端末の入力権限まで保護されたと扱ってはいけません。

### Firebase公式Auth Emulator: 6件成功

firebase-tools 15.34.1の公式Auth Emulator実装をループバックで起動し、合成データだけで確認しました。
エミュレータ内部の起動APIを使用するため、CLIのバージョンを固定しています。

- 正しい管理パスコードの受理、誤パスコードの拒否。
- 正しい秘密の回答の受理、管理資格情報との混同防止。
- パスコード変更後、旧パスコードが失敗し新パスコードが成功。
- 復旧アカウントの証明で管理アカウントのパスワードは直接変更できないこと。
- 無効化された管理アカウントの拒否。
- 復旧回答の検証後、権限を持つサーバーから管理パスワードを再設定できるプリミティブ。

最後のテストはエミュレータ専用の特権を用いた実現性確認です。
本番の復旧APIには、管理アカウントを更新できるサーバー用認証情報と、
セッション失効・誤入力制限・途中失敗への復旧処理が別途必要です。
エミュレータは本番の料金・全利用制限・実際のパスワード照合負荷を再現するものではありません。

### Cloudflare実環境: 前処理6回成功

- 合成データ専用のruntime-probe.mjsを既存の検証Workerへ配置。
- deployment_id: `57545674680447b2aeec37ed2fffca75`。
- /probeへの6回のアクセス全てでHTTP 200、ok:true。
- 同じバージョンのCloudflare invocation logsで6回全てoutcome:ok。
- 記録されたCPU時間: 1, 0, 0, 0, 1, 0ms（時系列順、整数表示）。
- FreeのCPU上限10msより小さい。ただし**前処理だけ**の計測。
- Firebaseへの実ログイン、セッションDB更新、入力権限確認を含むAPI全体の測定ではない。
- 検証終了後、workers.devとPreviewの公開を無効化し、APIで停止を確認。

従って「候補の軽い前処理は本番互換で低負荷」は確認できましたが、

## 実行

Node.js 24以降:

```sh
cd experiments/firebase-auth
npm install
npm test
npm run test:emulator
```

emulator.test.mjsはローカルのdemo-molkky-auth-proofのみを扱い、本番Firebaseへ接続しません。
FirebasePasswordProviderの本番向け接続先はHTTPSのIdentity Toolkit API固定です。
emulatorBaseはローカル試験専用で、明示的な127.0.0.1接続のみを許可します。
本番設定でこの試験用指定を使わないでください。
