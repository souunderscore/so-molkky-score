# so-molkky-score

ライブ配信用モルックスコアシステム「SÖスコア」。ブラウザで試合の得点・セット進行を管理し、OBSやStreamlabsのブラウザソースにスコアを表示します。

このREADMEは、現在の `index.html` と `overlay.html` の実装に基づく仕様です。

## 構成・動作環境

| ファイル | 役割 |
| --- | --- |
| `index.html` | 試合設定、投擲入力、勝敗判定、履歴管理、配信用データの送信 |
| `overlay.html` | 背景透過の配信用スコア表示、配信用データの受信 |

HTML・CSS・JavaScriptのみで構成され、ビルドやパッケージのインストールは不要です。操作用ブラウザではJavaScriptとlocalStorageを使用します。同一オリジン内の即時同期には、利用可能な場合にBroadcastChannelを使用します。

両画面はFirebase JavaScript SDK **10.12.0（compat版）** を `www.gstatic.com` から読み込みます。別端末への同期にはFirebase Realtime Databaseへの接続が必要です。SDKは旧Chromiumを利用する配信ソフトを考慮したcompat版ですが、対応ブラウザの最低バージョンは定義されていません。

## 起動方法

リポジトリのディレクトリで静的HTTPサーバーを起動します。Python 3がある場合の例です。

```sh
cd so-molkky-score
python3 -m http.server 8000
```

- 操作画面：`http://localhost:8000/index.html`
- 配信用画面：`http://localhost:8000/overlay.html`

静的ホスティングでも同じ2ファイルを公開できます。別端末から開く場合は、その端末から到達できるホスト名またはIPアドレスを使用してください。

## 基本操作

1. 「試合」タブで試合名（任意）、チーム数・チーム名、レギュレーション、目標スコア、最大ミス数を設定します。
2. 「試合開始」を押します。設定画面で上に並べたチームから投擲します。
3. 現在のチームが獲得した点数を **1〜12** のボタンで入力します。0点は「ミス 0点」で入力します。ピンの倒れ方から得点を自動算出する機能はありません。
4. セット終了後、次セットの投擲順を確認し、必要に応じて上下ボタンで変更してから次セットへ進みます。
5. 試合終了後は結果・セット分析を確認し、「同じメンバーで再戦」または「新しい試合」を選択できます。

試合中は直近8投分をチームごとの行で表示します。各投擲の✅／❌を押すと「狙い通り」の記録を切り替えられます。初期値は得点あり（バーストを含む）が✅、ミスが❌です。

「取り消し」は入力を戻すための操作です。通常モードでは、セット終了直後も最後の投擲を取り消して試合中に戻せます。このとき、脱落状態・相手への勝利得点・セット結果・セット勝利数・合計得点も元に戻します。次セットへ進んだ後は通常モードで前セットに戻れません。均一モードの制約は後述の「現状の制約」を参照してください。

設定画面の入力は入力時と設定変更前に保存されます。試合名・各チーム名の入力欄内の「×」で、その項目だけを空欄にできます。試合名のクリアは別途保存した名前も消し、チーム数・レギュレーション・投擲順は維持します。チーム数、レギュレーション、セット数やタブを変更しても、チーム名・試合名・最大ミス数を引き継ぎます。目標スコアは通常モード間では保持し、均一モードへの切り替え時は100点、均一から通常モードへ戻すと50点になります。

## 試合設定

| 項目 | 初期値・選択範囲 |
| --- | --- |
| 試合名 | 任意。非空の名前を試合開始時に別途保存し、設定画面で再利用 |
| チーム数 | 初期値2、2〜6チーム |
| チーム名 | 最大20文字。個別クリア可能。未入力時はチームカラーに対応する `SÖ`、`相手`、`相手２`、`相手4` などを自動設定 |
| 最初の投擲順 | 名前と色をセットで上下ボタンで移動。2チームは「先攻」「後攻」、3チーム以上は順番の番号を表示 |
| レギュレーション | 初期値は2セット勝負 |
| 目標スコア | 通常モードは初期値50。入力欄は10〜100 |
| 最大ミス数 | 初期値3。入力欄は1〜5。連続ミスによる脱落判定に使用 |

目標スコアと最大ミス数の上限は入力欄の属性です。開始処理は下限のみを補正するため、上限を厳密に検証する実装ではありません。

チームカラーは初期登録順にオレンジ、青、紫、緑、橙、赤で固定されます。セット間で投擲順を変えてもチームIDと色は維持されます。

### レギュレーション

形式はプルダウン、セット数または均一の目標点は数値で入力します。セット数に10セット等の上限は設けません。入力欄から離れた時点で、セット数は1以上の整数へ、均一の目標点は50点単位で切り捨て（最低50点）へ補正し、補正後の値を表示します。例えば120点は100点、175点は150点、75点は50点になります。試合開始時にも同じ補正を適用します。画面にはレギュレーションの説明文や補正通知は表示しません。形式と数値の高さをそろえ、区間目標は表示したままとします。

試合開始ボタンは画面下端に固定し、iPhoneのセーフエリアを考慮しています。名前のクリアと上下ボタンは44pxの操作領域を確保しています。

| モード | 選択肢 | 試合終了・勝者の決定 |
| --- | --- | --- |
| Nセット勝負（`match`） | 1以上の整数 | 指定セット数を実施し、セット勝利数が最多のチームが勝者。同率は引き分け |
| Nセット先取（`first`） | 1以上の整数 | 指定勝利数に最初に到達したチームが勝者 |
| Nセット合計（`total`） | 1以上の整数 | 指定セット数を実施し、セット終了時の合計得点が最多のチームが勝者。同点は引き分け |
| 11先（`eleven`） | 11セット先取固定、2〜6チーム | 通常は最初に11勝したチームが勝者。首位が10勝で並ぶと延長し、以降は首位が2位に2勝差をつけた時点で終了（延長上限なし） |
| プライム（`prime`） | 2チーム・4セット先取固定 | 4対0・4対1・4対2で終了。3対3になった場合は必ず全8セット実施し、5対3・4対4・3対5で終了。4対4は引き分け |
| N点均一（`uniform`） | 50点以上、50点単位（上限指定なし） | 50点ごとの区間をセットとして進行し、最終目標点に到達したチームが勝者 |

モードを切り替えると、勝負・先取・合計はN=2、11先はN=11、均一は100点に設定されます。均一から通常モードへ戻すと目標スコアは50点になります。

## メンバー別スコアシート

チームごとに任意でメンバーを登録できます。相手が未登録でも利用でき、未登録チームの記録は「投擲者」の1列に表示します。

1. 試合設定の「メンバーを追加」で名前を登録します。空欄のメンバーは試合開始時に除きます。
2. チェックした人がそのセットに参加します。上下ボタンで並べた順番に投擲し、各セットの先頭から循環します。登録済みのチームは参加者を1人以上選択してください。
3. 得点は従来どおりボタンを1回押すと記録します。各投には入力時点のメンバーID・名前を保存し、投擲者を自動で切り替えます。記録後の投擲者変更機能はありません。同名のメンバーはIDで区別します。
4. セット間で次セットの参加者と投擲順を変更できます。前セットの選択を引き継ぎ、過去のセットの名簿・投擲者は変更しません。
5. 試合画面・成績タブ・終了画面・履歴からスコアシートを開きます。メンバーを横、チームの投擲回を縦に並べ、得点・ミス・累積点・最終結果を表示します。各セットは前後ボタンで切り替えます。

### 得点・ミスの修正

- 試合中とセット終了直後は、当該セットの得点をタップして0〜12点へ修正できます。0点はミスです。終了画面では最終セットも修正できます。
- 次セット開始後、前セットは閲覧のみになります。履歴から開くスコアシートも閲覧のみです。
- 修正後は各投の累積点、バースト、連続ミス、脱落と勝敗を再計算します。投擲者は変更しません。
- 修正によって過去の投擲時点でセットが終了したり、新たな脱落・手番の矛盾が生じたりする場合は、戻す際に削除する投擲数を確認します。確認するまで元の記録は変更せず、キャンセルできます。確定すると整合する投擲までの記録を残します。
- 修正でセットが未終了になる場合はプレイ画面へ戻り、古いセット結果・勝利数・合計得点を取り除きます。試合全体が再開する場合は古い終了履歴も除きます。
- 試合終了直後の修正は終了履歴にも反映します。強制終了した試合の進行中セットもスコアシートと画像に含めます。

### 画像保存・共有

スコアシートの「全セットを画像で保存・共有」で、全セットを横に並べた1枚のPNGを生成します。名前、各投の得点・累積点、セット結果、試合名・形式・日付を含みます。画像内の `*` は目標点超過（バースト）です。

ファイル共有に対応した端末ではOSの共有メニューへ渡し、その他の環境ではPNGをダウンロードします。画像は端末内で生成し、画像生成用の外部サービスや追加ライブラリは使用しません。非常に大きな画像は解像度を調整し、それでも収まらない場合はエラーを表示します。

名簿と投擲記録は既存のlocalStorage状態に保存します。旧データにはメンバーを推測して割り当てません。狙いどおりかの新しい入力機能は追加せず、既存の狙い通り記録は維持します。

表の見せ方と全セットを1枚にまとめる方針は [Mölkky Maniaの参考システム](https://github.com/longbeachknit/molkkymania-score) を参考にしています。

## 投擲タイマー

スコア入力画面のチーム・投擲者表示の下、得点ボタンの上に、カウントアップの経過時間と「開始／停止／再開」「リセット」を横一列で表示します。メンバー未登録でも利用できます。

- 投げられる状態になったら「開始」を押し、モルックと動いているスキットルが止まったら「停止」を押します。0.1秒単位で表示します。
- 停止後はボタンが「再開」に変わり、停止時間を除いて保持した時間から計測を続けます。次の投擲は「リセット」→「開始」で0秒から計測します。
- 計測中の「リセット」は0秒から計測を続け、停止中の「リセット」は0秒に戻して停止したままです。
- 得点入力、取り消し、チーム切り替え、セット移動では自動停止・リセットしません。停止時間も次の計測まで保持します。得点を先に入力しても止められるよう、セット・試合終了画面にも操作を表示します。
- スコアシートや別タブを開いている間も経過時間を維持し、画面に戻った際に表示を更新します。ページを再読み込みしても計測状態を復元します。
- 新しい試合の開始、再戦、試合リセットでは、0秒・停止へ戻します。

開始時刻から経過時間を計算し、表示更新の間隔による遅れを積み重ねません。タイマーは操作端末内に保存し、投擲履歴・画像・配信用オーバーレイへの時間記録や自動の超過判定は行いません。

## 得点・セット進行の仕様

### 通常モード（勝負・先取・合計・11先）

- 各セットを0点から開始します。
- 入力した点数を加算し、目標スコアに**ちょうど到達**するとセット勝利です。
- 目標を超えた場合はバーストとなり、目標スコアの設定値によらず**25点**に戻ります。
- 0点で連続ミス数が増え、設定した最大ミス数に達すると、そのセットから脱落して得点は0点になります。
- 1点以上を入力すると連続ミス数は0に戻ります。バーストでもリセットされます。
- 脱落チームの手番はスキップします。生存チームが1つになると、そのチームの得点を目標スコアに設定してセット勝利とします。
- 次セットでは得点・ミス・脱落状態・投擲履歴をリセットし、セット勝利数とセット終了時の合計得点を引き継ぎます。

次セットの標準投擲順は、設定画面で決めた試合開始時の順番を「終了済みセット数 % チーム数」だけ循環移動した順です。3チームなら `A→B→C`、`B→C→A`、`C→A→B` と進みます。上下ボタンでの変更も可能です。

通常のNセット先取（`first`）で**全チームがN−1勝**になった次の決着セットは、終了済みセットの合計点が高い順を初期値にします。同点のチーム同士は、そのセットの通常の循環順を維持します。手動で並べ替えられ、変更した次セットのチーム順は再読み込み後も保持します。11先・プライムなど、ほかの形式の初期順は従来の循環順です。

操作画面のセット進行欄には、試合中は「終了済みセットの合計＋現セットの現在点」を**暫定合計**として表示します。セット間は現セットを含めた**確定合計**を表示し、次セットのチーム順の欄でも確認できます。均一モードの累積点は、通常モードのセット合計とは区別します。

### 11先モード

「11先」を選ぶと、先取セット数は11に固定します。チーム数は2〜6チームを選択でき、目標スコア・最大ミス数は現在の設定を保持します。得点、バースト、脱落、セットごとの参加者と投擲順は通常モードと同じです。

- 通常は最初に11勝したチームが勝利です。例：11・9・8なら首位の勝利です。
- 首位が10勝で並んだ時点で延長へ入ります。例：10・10・8。
- 延長後は、その時点の首位と2位の獲得セット数を比較し、2勝以上の差がついた時点で終了します。例：11・12は続行、11・13なら13勝のチームが勝利です。
- 延長中に別のチームが追いついた場合も、現在の首位と2位で判定します。例：11・10・12は続行、11・10・13で13勝のチームが勝利です。
- 延長にセット数の上限はありません。2セット連続で勝ったかどうかでの判定は行いません。
- 画面と配信用表示に延長状態を表示します。取り消し・得点修正で10勝の同率首位になるセット結果が取り除かれた場合は延長も解除し、再読み込み後も正しい状態で再開します。

### セット開始後の投擲順の修正

プレイ画面から、現在のセットのチーム順・参加メンバー・チーム内の投擲順を変更できます。

- **未入力**：「投擲順を変更」を開き、「この順で開始」で適用します。
- **入力済み**：「このセットをやり直す」を開きます。「この順でやり直す」で削除する投擲数を確認し、OKを押すと現在セットの記録だけを消して同じセット番号で開始します。終了済みセットの記録・勝利数・合計点・過去の試合履歴は保持します。
- 設定を開いた時点では、実際のチーム順や投擲記録を変更しません。「キャンセル」で元のプレイ画面に戻れます。設定中に再読み込みしても設定案を保持します。
- 1セット目の順番を修正した場合は、その順番を以後の循環の基準にします。それ以降のセットの手動変更は、そのセットの順番を変更します。
- 均一モードのやり直しは0点にせず、その区間の開始時の得点を復元します。破棄した投擲へ取り消しで戻ることはできません。
- タイマーは得点入力と独立しているため、投擲順の修正では自動停止・リセットしません。

### プライムモード

プライムを選ぶとチーム数は2、セット数は4、目標スコアは50、最大ミス数は3へ自動設定し、これらの入力欄は編集不可にします。別の形式に切り替えると再び編集できます。セット数の4は設定欄に表示します。

最初の6セットが3対3だったかをセット結果から判定するため、3対3になった直後に最後の投擲を取り消すと、全8セット実施の確定も解除されます。7セット目が4対3でも続行します。延長中の進行表示は「セット7/8」などになります。投擲順のローテーション・バースト・脱落・履歴保存は通常モードと共通です。

### N点均一モード

- 現セットの目標は `min(最終目標点, 現在のセット番号 × 50)` です。150点均一なら50点、100点、150点と進みます。
- いずれかのチームが現セットの目標にちょうど到達すると、そのセットを終了します。
- 次セットでは生存チームの得点を引き継ぎます。脱落チームは0点で復帰し、全チームの連続ミス数・投擲履歴をリセットします。
- バースト後の得点は**現セット目標 − 25点**です。目標100点の区間なら75点になります。
- 脱落によって生存チームが1つになった場合も、そのチームを現セット目標に到達させてセット勝利とします。
- 全チーム脱落時には、直前のセット結果を基に得点を復元して同じセットをやり直す処理があります。通常操作では生存1チームの時点でセット終了します。

## 結果・分析・履歴

試合終了画面には勝者、最終スコア、各セットの投擲数・狙い通り率・ミス回避率・得点・投擲詳細を表示します。

- **狙い通り率**：`intended !== false` の投擲数 ÷ 全投擲数 × 100（四捨五入）。
- **ミス回避率**：0点以外の投擲数 ÷ 全投擲数 × 100（四捨五入）。バーストも0点以外に含みます。
- 試合時間は開始から終了まで、セット分析の時間はそのセットの最初から最後の投擲までです。
- 終了画面の「最終スコア」表と勝者の得点表示は**最終セットのデータ**です。試合全体の勝者はレギュレーションの判定に従います。

「履歴」タブには終了した試合を新しい順に最大50件保存します。試合名、開始日時、試合時間、レギュレーション、セット勝利数、各セット得点を表示し、「投擲詳細を見る」で各セットの投擲を展開できます。均一モードでは累積得点と区間差分も表示します。

- 「試合終了」で強制終了すると、勝者なし（引き分け）で履歴に保存します。進行中セットはセット結果へ追加されません。
- 「試合リセット」は進行中の試合を破棄して設定へ戻ります。過去の履歴と設定値は保持します。
- 「履歴を削除」は保存済みの試合履歴をすべて削除します。
- リセット・強制終了・履歴削除には確認ダイアログがあります。

## OBS・Streamlabsへの表示

1. 操作画面に表示される「OBSオーバーレイ」のURLをコピーします。
2. 配信ソフトでブラウザソースを追加し、そのURLを設定します。
3. 幅は **420px** を目安にし、高さはチーム数や表示内容に合わせて調整します。ページの背景は透過です。
4. 操作画面で試合を開始し、入力が配信用画面に反映されることを確認します。

配信用画面には試合名・レギュレーション、現在の手番、得点、進捗バー、連続ミス、投擲数・ミス総数、セット勝利数・合計得点を表示します。直近の投擲は送信された最新20件から最新5投分の列を表示します。終了時は勝者と試合全体の投擲分析に切り替わります。

セット成績は丸をセット数分並べず、勝利数・合計得点を数値で表示します。

チームカードは2チームで横2列、3〜4チームで2列、5〜6チームで3列です。試合データがない場合や設定中は「試合待機中...」を表示します。

## 保存と同期

### ブラウザ内の保存

| localStorageキー | 内容 |
| --- | --- |
| `molkky_throw_timer_v1` | 手動投擲タイマーの開始時刻・停止時間 |
| `molkky_so_v2` | 設定、進行中の試合、セット結果、過去の試合履歴を含む操作画面の状態 |
| `molkky_live_state` | 配信用公開状態を `{ type: 'state', data: ... }` に包んだJSON |
| `molkky_game_name` | 最後に非空で保存した試合名 |

操作画面は保存済み状態を読み込んで再開します。履歴はブラウザ・オリジンごとの保存であり、Firebaseからは復元されません。ブラウザの保存データを削除すると、この端末の進行状態と履歴も失われます。

### 配信用データの流れ

- 操作画面は描画時などに公開状態を生成し、Firebase Realtime Databaseの **`game`** パスへ `set()` で全体を書き込みます。
- 同時にBroadcastChannel **`molkky_live`** へJSON文字列を送信し、localStorageにも保存します。
- 配信用画面はFirebaseの `game` の `value` イベントとBroadcastChannelを購読します。
- 配信用画面のlocalStorage読み込みは**初期表示時のみ**です。`storage` イベントの購読や定期ポーリングはありません。

公開状態にはフェーズ、試合名、チームID・色・得点・ミス・投擲数・セット成績、手番、目標点、レギュレーション、直近20件の投擲、終了済みセットの全投擲履歴、更新時刻を含みます。過去50試合の履歴は含みません。

同期は**操作画面から配信用画面への一方向**です。操作画面はFirebaseを購読せず、自分のlocalStorageを読み込みます。全操作画面が同じ `game` を上書きするため、現在の構成は1試合・1つの操作画面で運用します。

### Firebaseの接続先

現在は両HTMLに以下の接続先が直接記述されています。

```text
https://so-molkky-score-default-rtdb.asia-southeast1.firebasedatabase.app/
```

独自の環境で使う場合は、**両HTMLの `firebaseConfig.databaseURL`** を同じRealtime DatabaseのURLへ変更し、`game` パスの読み書きに必要なDatabase Rulesを設定してください。このリポジトリにはRulesや認証処理は含まれていません。実際のアクセス可否は接続先の設定に依存します。

## 現状の制約

- 均一モードの取り消しは投擲前のスナップショットを1つ保持する方式です。次セットの最初の投擲前なら前セット終了直前へ戻せますが、連続して何投も戻す履歴は保持しません。
- **均一モードのバースト表示に不一致があります。** 得点計算は「現セット目標 − 25」ですが、投擲チップには一律 `得点→25` と表示されます。
- **均一モードの「計」は最終累積得点とは異なります。** 共通の `setTotalScore` は各セット終了時の累積得点を加算するため、最終得点そのものはチームの現在得点を参照してください。
- 配信用画面の試合終了分析にある「全ターン」は、チームごとの全セット投擲数の最大値をさらにチーム数で割って切り上げています。操作画面のセット分析とは算出方法が異なります。
- Firebaseの書き込み完了を待つ処理、接続状態の表示、Promiseの書き込みエラーを画面へ通知する処理はありません。SDKの読み込み失敗時も、配信用画面の初期化が途中で止まる可能性があります。
- 配信用画面はFirebaseの値が空になっても既存表示を消しません。待機表示へ戻す場合は操作画面で試合をリセットします。

## 開発時の確認

回帰テストにはメンバーの参加選択・ローテーション・セットごとの名簿、得点修正と再計算、終了履歴の整合性、編集ロック判定、旧データの互換性を含みます。画像とOS共有メニューはブラウザでも確認してください。

パッケージ設定・ビルド設定はありません。Node.jsがある場合は、以下のコマンドで取り消し、設定入力保持、均一の補正、個別クリア、投擲順とチームID・色の保持の回帰テストを実行できます。HTML内の実際のゲーム処理を実行するテストで、ブラウザ・Firebase・OBSの結合テストは含みません。

```sh
node tests/regression.cjs
```

変更時は静的サーバー上で操作画面と配信用画面を開き、次の操作も確認します。

- 目標点への到達、バースト、連続ミスによる脱落と手番スキップ。
- 各レギュレーションの勝敗、均一入力の50点単位への切り捨て、セット数が大きい場合の表示。
- 設定画面とセット間の投擲順、チームカラーの保持、均一モードの得点引き継ぎ。
- 試合名・チーム名の個別クリアと再読み込み後の状態。
- 取り消し、狙い通りの切り替え、終了後の履歴、再読み込み後の復元。
- 同一オリジンでの表示同期と、Firebase経由の別端末での表示同期。
